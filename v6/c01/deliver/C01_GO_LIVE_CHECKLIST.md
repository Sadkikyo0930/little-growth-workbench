## 2. 当前学习日

### 2.1 候选会算出什么（可复现，不含猜测）

```
计划序列        [1, 1, 1, 2, 2, 1]
plan_max_day    2          high-water 日期 2026-11-11（第一次到 day2）
latest_day      1          → 1 < 2  ⇒ corrections_required = [PLAN_HISTORY_ROLLBACK]
回退行          2026-11-13 day1（1 行）
记录 day 集合   [1, 6, 9]  （快照里可见，但**不参与阻断判定**）
硬阻断码        []         → 窗口 [3, 3]，唯一允许值
```

**为什么 day6 / day9 记录不会触发硬阻断**（这一条必须写清，否则容易被误判为漏检）：
`RECORD_DAY_AHEAD_OF_PLAN` 与 `DEVICE_DAY_DISAGREEMENT` 用的都是 `v_latest_rec_days`，它的定义不是「所有记录的 learning_day」，而是「**记录日期落在最新计划日（2026-11-13）那一天的**记录的 learning_day」。
- 数学 day6 的记录日期是 2026-11-06，语文 day9 是 2026-11-09 —— 都不在 11-13，**不进这个集合**
- 11-13 当天**一条记录都没有**（day1 的英语完成于 11-12、科学完成于 11-11）→ `v_latest_rec_days` 为空

所以两个记录类硬阻断都不成立。**但这也意味着判定是脆弱的**：只要 11-13 那天存在任意一条 `learning_day > 2` 的记录，就会立刻变成 `RECORD_DAY_AHEAD_OF_PLAN` 硬阻断，窗口全部作废。F 阶段实施当天必须重新查一遍这个集合，不能沿用今天的结论。

### 2.2 家长必须确认的最少信息（只问 3 个问题）

1. **孩子 2026-11-13 那天实际学的是哪一天的内容？**（系统里 11-13 的计划是 day1「英语+科学」，但当天没有任何 day1 的完成记录）
2. **11-11 与 11-12 的 day2「语文+数学」，孩子是学完了、还是被旧设备顶成了 day1 的内容？**（这两天计划是 day2，但落库记录全是 day1）
3. **现在还打算按计划推进到 day3 吗？**（因为候选只会接受 day3，且它意味着 day2 的内容不再补）

不需要家长确认的内容：两科是否完成（系统证据已足够）、是否已经继续推进（`r5_family_progress` 不存在，**从未推进过权威日**）。

**备份能力的真实边界（必须承认）**：本环境 `TenantType=SHARED`，只支持 SDK / 网关访问，**没有 TCP 直连、没有私网 host**，因此 `pg_dump` / `pg_basebackup` / `psql` 这类物理或逻辑全量备份**在本轮权限下做不了**。能做的只有「经网关的只读聚合快照」——它能证明数据没变，但**不能用来 restore**。所以回滚路径只有一条：`900_rollback.sql` 把结构改回去，数据侧靠「候选本身不删改任何既有行」这个性质兜底（这一点已在独立实例上按 `count + md5` 逐表验证过）。

如果要求「先有可 restore 的备份再放开 B」，那么本环境当前条件**不满足**，需要走 CloudBase 控制台的手动备份/回档能力（本轮未验证该入口是否对 `baas_personal` 开放）——这是 §5 里应当补的一条。

**B3 已部分完成**：3 个 `codeSha256` 与 38 个函数 ACL 已采集（见证据 JSON）。**B1 的完整 dump 尚未做**——因为它需要写文件到本地并可复现，建议在 B 阶段开始前 10 分钟内现场执行，避免拿到过期快照。

### 3.2 不能做的（本轮明确禁止）

- 任何 `CREATE / ALTER / DROP / GRANT / REVOKE`（含在独立 schema 里试跑）
- 任何 `INSERT / UPDATE / DELETE`（含 `r5_acl_baseline` 的首次写入）
- `CREATE OR REPLACE FUNCTION` 替换 `r5_gate_status_core` / `r5_publish_today`
- 云函数更新、静态托管上传、Pages 更新、main 合并

### 3.3 共享实例的真实风险（必须书面承认）

`normal-goose-d5g4qyzr8bb389a4a` 只有一个实例，`TenantType=SHARED`，没有第二个环境可切。所以：

| 变更 | 作用范围 | 能否只影响测试家庭 |
| --- | --- | --- |
| 5 张新表 + 10 个新函数 | 全库新增，正式家庭不被调用则无感 | ⚠️ 部分（对象共享，调用可控） |
| **`r5_daily_plan` 加 BEFORE 触发器** | **共享表**。正式家庭一旦有 progress 行，今日计划写入即受 `R5_PLAN_DAY_REGRESSION` 约束 | ❌ **不可能只影响测试家庭** |
| **替换 `r5_publish_today`** | **共享函数**。正式家庭发布计划走新逻辑；未初始化时**失败关闭** | ❌ **不可能只影响测试家庭** |
| **替换 `r5_gate_status_core`** | **共享函数**。正式家庭闸门走包装器（降级但可用） | ❌ **不可能只影响测试家庭** |

结论：**「只给测试家庭初始化权威日」并不能把风险限制在测试家庭**。B 阶段一旦执行，正式家庭的计划发布路径立即改变。这是必须在授权书上明确的一句话。
